# Linux qualifying acceptance run

A qualifying automated acceptance result for the current build is three verdicts on one repository revision and packaged add-on version: a passing Static run (pytest, Script API type check, project validation, packaging), a passing full Scenario Run (every configured scenario, gameplay asserted through the Simulated Driver's input path), and a passing Linux Client Smoke Run (the real client loads the Dedicated Test World with our packs, the retained screenshots pass, and Minecraft shuts down normally). This replaces the single uninterrupted Windows run that issue #25 and the #24 spec required, where the real client also asserted gameplay through its content log. We chose this because development moved to Linux, where the Android-based client never surfaces script output (ADR-0016), so client-side gameplay assertions are impossible there and the Scenario Run is the gameplay authority. The Windows runner stays in the repository and still works for anyone on Windows, but it is no longer required for acceptance. Manual Proving Ground observations remain required for input feel, visuals, audio, and camera; no automated verdict substitutes for them. Approved by the maintainer on 2026-10-03.
