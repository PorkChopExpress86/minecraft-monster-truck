# Headless Scenario Runs with a Simulated Driver

Driving mechanics are verified by Scenario Runs: a disposable, version-pinned Bedrock Dedicated Server container (`itzg/minecraft-bedrock-server`, digest-pinned, same Minecraft version as the client, private network, no host ports, removed after each run) hosts a generated Scenario World in which a GameTest Simulated Driver boards the Driver Seat and supplies real movement, steering, and jump input while a separate test-only pack asserts observable outcomes, including the `blake:pitch_angle` property for Dynamic Incline Pitch. We chose this over injecting keyboard input into the real client because Wayland input injection needs a privileged daemon, steals the desktop, and is not repeatable in CI, and over pushing the truck with scripted impulses because that would bypass the player-input path the mechanics depend on. The Scenario World alone enables the Beta APIs experiment that `@minecraft/server-gametest` requires; the distributable packs stay on stable `@minecraft/server` 2.10.0 and never reference GameTest. This extends ADR-0007: the real-client Client Smoke Run still never generates input and remains the source of screenshots for human visual review, while the user's long-lived server containers are never used for testing. If the Simulated Driver cannot drive the truck through its input path, this decision must be revisited rather than silently replaced with scripted impulses. On Linux the real client cannot serve as an assertion channel at all: the Android-based client launched through mcpelauncher never writes script console output to its content log or standard output, so the Linux Client Smoke Run passes on world load and screenshots alone and all gameplay verdicts come from Scenario Runs. A Simulated Driver exists as a player object only in the script runtime that spawned it, so the scenario driver runs inside a Scenario-World-only copy of the add-on's behavior pack whose entry imports both the add-on's scripts and the driver; that copy therefore runs on the `@minecraft/server` beta version the GameTest module requires instead of the shipped stable version. Because a Simulated Driver cannot press the Jump button, the add-on exports `requestDriverJump(player)`, the same function its Jump-button handler calls, and Suspension Jump scenarios call it to supply the driver's jump input.
