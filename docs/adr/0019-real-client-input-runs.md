# Real-client input runs with a virtual keyboard

A Client Input Run drives the real Linux client with key presses from a user-level uinput virtual keyboard and asserts what happens in the client's own world. This reverses the part of ADR-0016 that ruled out input injection. ADR-0016 said Wayland injection needs a privileged daemon. It does not on this machine: `/dev/uinput` carries a uaccess ACL for the seat user, so a pure-Python device works with no root and no daemon. The other two objections still hold, and they set the limits. Injected keys go to whichever window has focus, so a focus guard (a KWin script reporting the active window through the user journal) must see the launched Minecraft window before every press, and any other window aborts the run with every held key released. The run is also not repeatable in CI, so it is a local `./test-addon.sh Client` mode, never part of All.

The assertion channel is the client's own WebSocket client. The run types `/connect 127.0.0.1:<port>` into chat, and a standard-library server sends commands as the player. `querytarget` returns positions and facing, and scoreboard reads return what the test-only harness, in probe mode, publishes every tick: the player's seat, ticks spent out of a seat, and the Sneak, Jump and look state. The run turns on `websockets_enabled`, turns off `websocket_encryption`, and binds Sneak to K for its own duration only, then restores those keys and keeps the game's other changes to options.txt. Sneak is rebound because a virtual Shift never reaches this launcher as Sneak, though a real Shift does. Virtual mouse motion turns the view only once the pointer is over the game window, and a mouse-look check was dropped because the `steering` scenario already proves that look direction does not steer.

The first runs found a defect that Scenario Runs could not show. Minecraft itself dismounts a rider who presses Space, and in this client a Sneak exit never reads as sneaking or as the Sneak button on the riding player. The add-on had re-seated every non-sneaking exit, so Sneak could never get a player out, and a Space dismount was hidden by a re-seat within the same tick. The add-on now re-seats only an exit that comes with Jump held, now or within three ticks, or that happens while the truck is falling or settling from a landing. A Space re-seat opens no landing window, so Sneak works as soon as the handbrake is released. On steady ground any other exit is Sneak and is let go. Approved by the maintainer on 2026-10-04.
