# Dynamic Incline Pitch and Coordinated Four-Wheel Steering Architecture

We decided to:
1. Implement **Dynamic Incline Pitch** via dual-axle ground contour probing (+1.125m front axle, -1.125m rear axle along heading) calculated in the Script API tick loop. The terrain elevation gradient $\arctan(\Delta Y / L)$ is clamped to $\pm 35^\circ$ with exponential smoothing (factor 0.20 per tick) to prevent camera clipping and visual jitter during 2-block Controlled Auto-Steps, while airborne states blend into trajectory-aligned launch and landing angles, and liquid flotation returns to level ($0^\circ$).
2. Synchronize vehicle pitch angle from server to client through a client-synced integer entity property `blake:pitch_angle` (clamped $[-35, 35]$), driving visual $X$-axis rotation of the `root` bone so that the chassis, suspension, and all four tires maintain Dynamic Incline Pitch in alignment with terrain gradients as an authentic rigid multi-link assembly.
3. Decouple wheel steering yaw from tire rolling spin in the geometry model by introducing four dedicated steering knuckle bones (`steer_fl`, `steer_fr`, `steer_rl`, `steer_rr`) parented to `root`, with the original `wheel_*` bones re-parented under their respective steering knuckles. This eliminates Euler gimbal coupling and prevents tires from wobbling or rolling laterally during continuous movement.
4. Implement **Coordinated Four-Wheel Steering** using counter-phase kinematics: the front steering knuckles deflect up to $\pm 26^\circ$ into the turn, while the rear knuckles counter-steer up to $\mp 18^\circ$ (a $0.692$ counter-steer ratio).
5. Drive steering angle via angular yaw velocity tracking and a dynamic hydraulic centering spring in the Script API, synchronizing via client-synced integer entity property `blake:steer_angle` (clamped $[-26, 26]$), ensuring smooth progressive turn entry and automatic return-to-center when driving straight, reversing, or parked.
